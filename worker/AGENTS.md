# Worker Rules

## Scope And Source Of Truth

- These rules apply to the worker runtime in `worker/`.
- Provider failures must be classified into stable domain codes before retry, finalization, persistence, or logging. Do not expose raw SDK/provider errors.
- Provider startup preflight must make one bounded synthetic, non-document request through the same transport, schema, and decoder as quiz generation; validate the full provider-owned Quiz structure and never log its payload.
- Before a PR, provider/model/preflight changes must pass the worker build and affected tests plus exactly one local real-alias full-quiz `ai-worker preflight` using runtime environment; dev only validates deployment-specific wiring/E2E.
- Before a PR, worker lifecycle, concurrency, timeout, or shutdown changes must pass `go test -race ./...` and one local executable smoke (for example `ai-worker preflight` with the fake provider or the configured real alias); if PostgreSQL/object storage are unavailable, record that full startup/E2E evidence is not covered.
- Any JSON value crossing from Go to the Node return seam must preserve fields required by the versioned handoff contract even when their valid value is zero; cover that serialization contract with a regression test before emitting `ai.outbox`.

- Build every PostgreSQL connection from `config.Database.PoolConfig()`/`ConnConfig()`; never pass a raw URL to `pgxpool.New`/`pgx.Connect`. pgx defaults to `sslmode=prefer` (unverified TLS with plaintext fallback), and the verified TLS policy is applied only by those builders. Both verify modes must check the host name like the API's node-postgres `verify-ca`; never weaken one runtime for the same `DB_SSL_MODE`. pgx CancelRequest stays plaintext (PID + cancel key only). When `DB_HOST` names a TCP forwarder (media probe → `media-probe-db-egress`), keep verification on the real server via `DB_SSL_SERVER_NAME`; never use `InsecureSkipVerify` or a custom `VerifyPeerCertificate` to make a forwarder name pass.
- A runtime selected by an egress NetworkPolicy (media probe) must not fail on its first PostgreSQL attempt: kube-router can reject a new pod's IP for a few seconds. Bootstrap Ping retries only transient errors (refused, reset, timeout, EOF before the SSLRequest reply, and SQLSTATE 57P01/57P03/53300) with bounded backoff and a total budget, fails at once on other SQLSTATE, x509 and TLS handshake errors (any failure after the server answered the SSLRequest is stage `tls`), exits 0 on SIGTERM (`databaseBootstrapResult`), and stays unready until Ping succeeds. Log only `database_stage`, `sqlstate`, and `attempts` from `ClassifyDatabaseError`; never a raw pgx error, which echoes host and user.
- Every S3 client behind an egress allowlist (Squid `media-egress-proxy`) must pin the configured host: call `SetS3EnableDualstack(false)` after `minio.New` and never enable transfer acceleration. minio-go v7 rewrites Amazon endpoints to `s3.dualstack.*` by default, which Squid rejects with 403 (#210). Also pin `Options.Region` from a regional endpoint and fail fast when an Amazon endpoint has no region: otherwise minio-go discovers it via `GET ?location`, a least-privilege credential gets AccessDenied, and minio-go silently falls back to `s3.us-east-1.*`. Test through a fake proxy that records the host each request is really sent to; checking only the configured endpoint string does not catch the rewrite.
- Long-running work that a deletion or lease fence can invalidate (per-chunk provider calls, media download/ffprobe) must stop as soon as the fence is lost, not only at the final transactional write. Run a fixed-interval `CheckActive` monitor that cancels the work context, and on a confirmed `ErrJobFenceLost` end as fenced without retry, finalization, or persistence. The two runtimes intentionally differ on a transient `CheckActive` read error: the AI worker (`consumer`) checks the context before each paid provider call and cancels only on `ErrJobFenceLost`, keeping already-paid output and leaving `PersistAndComplete` as the transactional gate; media-probe (`mediaprobe`) fails closed on any read error and hands it to `finishFailure`, because download/ffprobe has no paid output and is cheap to repeat. Do not align one runtime to the other without an explicit decision and a regression test for the new behavior.

## TEXT_EXTRACT Jobs

- `TEXT_EXTRACT` (ADR-0033) shares `ai.processing_jobs`, claim, lease, retry and DLQ with `FULL_PIPELINE`, but must stop after extract + chunk: it never calls the provider, never writes `ai.chunks`, and ends only through `CompleteExtraction` (job `COMPLETED` + `ai.outbox` `DocumentExtractionCompleted` in one fenced transaction: attempt, lease, cancellation marker, revocation). `extractedChars` counts runes, not bytes. Go never writes `course.*` or the wallet; Node reserves from this measurement. A `FULL_PIPELINE` job still re-extracts on its own, so the job must stay correct without any state left by `TEXT_EXTRACT`.

## Usage Reporting

- Mỗi attempt đã claim mang một `UsageTracker` trong context; provider adapter ghi `Dispatched` trước khi gửi, rồi `Reported` (có token) hoặc `Rejected` (non-2xx) khi có phản hồi. Lời gọi không có phản hồi hoặc 2xx không có `usage` là `uncertainDispatches` để Node giữ `HELD`; không đoán token. Store đính khối `usage` vào mọi payload `DocumentProcessingResult` và context persist mới (sau deadline) phải gắn lại cùng tracker.

## Media STT

- Real speech-to-text for AUDIO/VIDEO (#160 PR5) runs only in the full-pipeline worker behind `AI_MEDIA_STT_ENABLED` (strict `true`/`false`, default off; the `STT_*` settings are read only when on and never reach `media-probe-worker`). With the flag off, media keeps the pre-existing behaviour. `STT_BASE_URL`, `STT_API_KEY` and `STT_MODEL` stay separate from `OPENAI_*`.
- `HTTPTranscriber` never retries or falls back, does not follow redirects, and validates `verbose_json` strictly (`segments` present, finite ordered non-negative times). Classify by cost, not only by status: 2xx is billed (even with an unusable body: `TRANSCRIPTION_OUTPUT_INVALID`), 408/5xx/transport/timeout/cut body is uncertain and technical, 429/401/403/404/3xx are technical rejections that cost nothing (operator config such as a rotated key or wrong base URL must not blame the user's file), and only the remaining 4xx (400/413/415/422...) is business `PROVIDER_INCOMPATIBLE`. No provider text in errors or logs.
- Persist every paid or uncertain chunk dispatch through `SaveSTTOutcome` (small transaction + `lockActiveJob`, on a context detached from cancellation) into `ai.media_stt_chunk_results`; a retry resumes from checkpoints that have segments. The terminal transaction (`PersistAndComplete`, `finalize`, `finalizeWithDLQ`) sums and deletes the checkpoints so `usage.sttBilledSeconds`/`sttUncertainSeconds` cover every attempt exactly once; a scheduled retry keeps them. A definite billed answer resolves any uncertain dispatch of the same chunk (owner decision): the upsert keeps `billed_ms` as the largest value (a chunk is billed once) and zeroes `uncertain_ms`, in either arrival order, so carried and persisted outcomes never double count; only chunks that never got an answer keep uncertain seconds (HELD, resolved by the #275 reconciler). Retry a failed checkpoint write a bounded number of times (never after `ErrJobFenceLost`); if it still fails, carry the outcome on the `UsageTracker` (`AddUnsavedSTT`) so the next job-locking transaction writes it. Bill the chunk body span (no overlap) and verify each chunk's manifest `sha256` after reading it by VersionId.
- Check the fence before each paid STT call (only `ErrJobFenceLost` stops it) and run STT inside `withActiveFence`. Do not write shared maps from STT goroutines while the scheduler loop reads them; merge after `Wait`.
- Media Documents cap questions at `MaxMediaQuestions` (30, evenly spread over the timeline) and generate with bounded concurrency; PDF/TEXT stay sequential and uncapped.

## Processing Failure Logging

- Every processing retry or final failure must emit one safe structured event when the outcome is known: retry scheduled, retry persistence failed, final failure persisted, final-failure persistence failed, or persistence outcome ambiguous.
- Use stable event names and include only bounded operational metadata needed for correlation and diagnosis, such as phase, attempt, job identifier, correlation identifier when available, failure code, and outcome. Keep event fields consistent across error paths.
- Never log request or source content, prompt, generated questions or answers, credentials, provider responses, raw error messages, stack traces, storage references, or other payload data. Safe codes and fixed messages are the contract.
- A persistence or commit error whose final state is uncertain is an explicit `persistence_ambiguous` event. Do not silently retry or represent that state as a confirmed final failure.
- A malformed store outcome is an explicit `worker.processing.retry.contract_violation` event with bounded phase/category metadata; fail closed without treating it as persistence success.
- Normal polling and no-work cycles remain silent; logging is for startup/shutdown, real work, retry/backoff, and failure outcomes.
- Emit `worker.processing.completed` only from an explicit completed outcome; a successful retry schedule or DLQ finalization is a non-completion outcome so durable replays cannot be logged as completions.

## Tests

- The local document E2E harness must export a sanitized Google OAuth fixture before starting the API; `GoogleOAuthClientProvider` is eager, so the harness must not depend on a developer's `app/.env`.
- When using `psql` variables in a fixture, pipe the SQL through stdin; `psql --command` does not interpolate `--set` variables in this runtime. Keep fixture output redirected and never expose generated tokens or credentials.
- Tests for processing failures must assert the structured event name, normalized level, and safe metadata for scheduled retry, retry persistence failure, final failure, final-failure persistence failure, and ambiguous persistence outcomes.
- Add assertions that forbidden payloads and raw provider/error text do not appear in emitted events. Keep these tests at the logger/consumer boundary so future error paths cannot bypass the contract.
- When a harness runs a host binary instead of the release image (for example native `ffprobe` in the local document E2E), derive the expected version from that binary; never copy the image artifact pin, which only matches the image and makes the worker exit at its version check. Keep the production pin in `worker/Dockerfile` and the Kubernetes manifest.
- Every CI job that runs the worker Go tests (`worker-ci.yml` quality and `deploy-dev.yml` worker-quality) must install the same test toolchain, including `ffmpeg`/`ffprobe`, before `go test ./...`; a dependency added to one job must be added to the other, and the deploy workflow policy test asserts this.
- CI installs `ffmpeg`/`ffprobe` only through `worker/scripts/install-media-tools.sh`, which downloads the BtbN artifact pinned by the `FFPROBE_*` ARG literals in `worker/Dockerfile` and verifies its SHA-256 and reported version. Never `apt-get install ffmpeg` in a workflow: the Ubuntu mirror pulled 99 packages in ~600 s (run 38032634393) and the version is unpinned; `deploy/dev/tests/test-media-tools-ci.sh` rejects it.
- BtbN deletes daily `autobuild-*` releases after ~2 weeks (a stale pin 404s every backend CI and `media-probe` image build, #265); pin only a month-end build (`FFPROBE_RELEASE` date is the last day of its month). The media-probe image carries `ffmpeg` from the same archive: change `FFPROBE_RELEASE`, `FFPROBE_ASSET`, `FFPROBE_SHA256` (self-downloaded), `FFPROBE_VERSION`, `FFPROBE_BUILD_VERSION` (from the binary's `ffprobe -version`; `ffmpeg -version` must report the same build), `MEDIA_PROBE_FFPROBE_VERSION` and `MEDIA_PROBE_FFMPEG_VERSION` in the Dockerfile and `infra/k8s/apps.yaml.j2` together; `deploy/dev/tests/test-media-tools-ci.sh` rejects a non-month-end release.
- Derived audio (ffmpeg chunks under `derived-audio/`, #160) stays behind `MEDIA_PROBE_AUDIO_PREP_ENABLED` (strict `true`/`false`, default off) and runs only inside `media-probe-worker`. ffmpeg uses the ffprobe sandbox contract (absolute path, no shell, closed stdin, minimal env, `-protocol_whitelist file`, demuxer allowlist, `-threads 1`, `-fs` cap); every run is cancelled by the `CheckActive` monitor. Record each exact S3 `VersionId` per chunk through `SaveAudioChunk` (advisory lock `media-probe:<document>:<owner>` + `lockActiveJob`) right after its `PutObject`, never only in `Complete`, so Document deletion either sees the row or fences the save. Probe credentials may `PutObject` under the prefix only; never add Delete to them, and keep derived-audio failures free of keys, buckets and raw S3 text in logs.
